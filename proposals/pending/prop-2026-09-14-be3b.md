Retour sur le rendu de `build_catalogue.py` (base `el2d-referentiel`), constaté en diagnostiquant une perte de décimales sur le grid des lignes de commande de BPM_ACHAT.

Trois informations présentes dans les XML n'apparaissent pas dans les fiches `-contenu.md`, alors qu'elles sont exactement ce qu'il faut pour suivre une valeur de bout en bout :

1. **Les affectations des instructions `insert` et `update`** — la fiche rend le support cible, mais ni les champs alimentés ni leurs sources et fonctions inline (ex. `article_prix_unitaire_ht ← lvd_Prix_Unitaire`, avec ou sans `toNum`). Les `assign` sont rendus, les `insert`/`update` non.
2. **Les paramètres `OUT` (et `ERR`) des traitements Service d'écran** — seuls les `IN` sont listés ; on ne voit pas où atterrit un résultat de service (composant, message BPM, entrée d'un autre traitement), alors que la grammaire `<paramOUT objects="…">` est documentée dans `phoenix-blueway:/designer/projets-objets/format-export-ecran.md`.
3. **Le texte des traitements Formule d'écran** (composants `id="131"`) — seul le nom est rendu.

Conséquence : impossible de trancher depuis la base seule si une troncature vient d'un mapping serveur ou de l'affichage ; il a fallu passer par la Supervision. Demande d'évolution : rendre ces trois éléments dans les fiches `-contenu.md` (même mise en forme `cible ← source — fonction=…` que les `assign`), ou à défaut exposer les XML source via `kb_read` pour les cas où la fiche ne suffit pas.
