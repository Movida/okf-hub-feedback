`kb_search` renvoie une erreur `IO_ERROR: ripgrep (rg) introuvable dans le PATH — il est requis par kb_search (voir .devcontainer/devcontainer.json)` sur tout appel, quelle que soit la base interrogée (`el2d-blueway`, `el2d-referentiel`), sur des requêtes simples type mot-clé unique. Reproduit trois fois de suite, sur deux bases différentes, dans la même session.

`kb_list` et `kb_read` fonctionnent normalement dans la même session — le problème est spécifique à `kb_search`, cohérent avec une dépendance binaire (`rg`) manquante dans l'environnement d'exécution du hub plutôt qu'un bug de code.

Contournement utilisé en attendant : navigation manuelle via `kb_read` sur `index.md` de chaque base puis sur les sections/sous-index pertinents (fonctionne, mais plus lent et incomplet — impossible de retrouver un terme précis sans connaître déjà le document probable).

Impact : toute session qui suit le mode d'emploi standard (`kb_search` en premier réflexe, cf. `okf-hub-guide`) échoue dès le premier appel et doit improviser un contournement, sans indication que la cause est un environnement cassé plutôt qu'une base vide ou une requête malformée.

Suggestion : installer `ripgrep` dans l'image/devcontainer du hub, ou à défaut faire échouer `kb_list` avec le même message au démarrage pour signaler le problème avant que la session ne perde du temps sur `kb_search`.
