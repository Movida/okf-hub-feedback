Un appel `kb_search(base="el2d-referentiel", query="ACH_BPM_ECR000_Commande_Modele")` a échoué avec :

```
ERROR: IO_ERROR: ripgrep (rg) introuvable dans le PATH — il est requis par kb_search (voir .devcontainer/devcontainer.json)
```

Dans la même session, au même moment, `kb_list` et `kb_read` (y compris avec `section:` et `force: true`) fonctionnaient normalement sur plusieurs bases (`phoenix-blueway`, `el2d-blueway`, `el2d-referentiel`) — seul `kb_search` est impacté, cohérent avec une dépendance binaire externe (`rg`) absente de l'environnement d'exécution du hub sur ce device, plutôt qu'un problème de configuration des bases elles-mêmes.

**Contournement utilisé** : abandonner la recherche plein texte, lister la table des headings d'un document volumineux (`kb_read` sans `section`, qui bascule automatiquement sur cette table au-delà du seuil de taille) puis cibler les sections par titre. Cela a suffi pour la tâche en cours, mais alourdit nettement la navigation sur une base volumineuse (856 documents sur `phoenix-blueway`) quand on ne connaît pas déjà le document ou la section pertinente — c'est exactement l'usage que `kb_search` est censé couvrir en premier réflexe (cf. le guide de routage d'une question).

Environnement : device "port-el2d105", session Cowork, 2026-09-01.
